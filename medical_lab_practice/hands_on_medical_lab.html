Start here: your first 10 minutes

You can use the complete setup script embedded below, even if this HTML is the only file you keep.

Easiest route: browser, no installation

  1. Open SQLite Fiddle in a second browser tab. Wait for its input editor and Run button.
  2. Expand “Full setup script” below and click Copy SQL. This is a new four-table dataset, separate from the small first guide. Use a fresh playground tab or a separate practice database.
  3. Replace the playground’s input text with the script. Clear any partial selection and click Run.
  4. Replace that text with the verification query below. Click Run. Compare the output to the table.
  5. Go to Activity 1. Copy its query into the same input area and click Run. Read the output below or beside the input.
  6. Try its exercise before expanding the solution. Replacing query text does not remove the database.

Save your progress: use Download DB in Fiddle before closing or refreshing. Use Load DB… to resume. Save your own queries separately in a text file named practice.sql. Browser data is temporary by default.

Ready-to-open local database

The ZIP package includes lab_training.sqlite. In DB Browser choose Open Database, select that file, and open Execute SQL. Paste one query, use the execute/play control, and inspect the result grid. In VS Code with SQLite by alexcvzz installed, use SQLite: Open Database, create practice.sql, use SQLite: Use Database, then SQLite: Run Query. Press ⌘⇧P to find these commands. You do not need to import the CSV files.

For installation help, see the original guide’s setup section, VS Code installation, SQLite extension instructions, or DB Browser downloads.

See how the data connects

  • specimens: one received specimen per row. Five are rejected; the other 55 each have two result records.
  • results: one ordered assay per specimen per row. There are 104 finalized and 6 pending results.
  • assays: the test catalog, including units and compatible specimen type. Lactate deliberately has no result records.
  • qc_runs: one control-material measurement per row. Ten Glucose runs and ten Hemoglobin runs share a fictional control lot and level.

There are no patient identifiers or diagnoses. The time range is fixed. All timestamps are naive local training times, with no time-zone conversion. Source area and specimen type are deliberately patterned; do not infer real-world relationships from these data.

Important counting trap: 60 specimens is not 110 patients. Joining specimens to results repeats each accepted specimen twice. Count specimens from specimens, or use COUNT(DISTINCT s.specimen_id) after a join.

Final challenge: specimen acceptance report

Report received specimens, rejected specimens and rejection percentage for each specimen type. Use all 60 received specimens as the overall population; each group has its own denominator. Do not join results, because that would remove rejected specimens and multiply accepted ones.

New tool: CASE WHEN is an if/else expression. Give a rejected row 1 and an accepted row 0; SUM adds the rejected rows. Multiply by 100.0 for a percentage using decimal division.

  1. Start with the count-by-type query from Activity 3.
  2. Add the SUM(CASE…) rejected count.
  3. Divide rejected by received, multiply by 100.0 and round to one decimal.
  4. Write one sentence describing the denominator and one sentence explaining why the tiny synthetic dataset cannot establish a real rejection benchmark.
Complete solution
SELECT specimen_type, COUNT(*) AS received,
 SUM(CASE WHEN acceptance='Rejected' THEN 1 ELSE 0 END) AS rejected,
 ROUND(100.0*SUM(CASE WHEN acceptance='Rejected' THEN 1 ELSE 0 END)/COUNT(*),1) AS rejection_pct
FROM specimens GROUP BY specimen_type ORDER BY specimen_type;
Expected output
specimen_typereceivedrejectedrejection_pct
Plasma20210.0
Serum2015.0
Whole blood20210.0

Each percentage uses all received specimens of that type. These data were generated for practice and are not a measured rejection rate from a laboratory.

Help and data dictionary

If something goes wrong

  • No such table: load this workbook’s setup script into the current database. The earlier guide uses different tables.
  • No output: run a complete SELECT ending in a semicolon. Clear accidental text selection before executing.
  • Wrong row count: rerun the reset in a dedicated practice database and run the verification query.
  • CSV empty cell: these exports represent SQL NULL as blank. Do not convert missing results to zero. CSV does not retain database keys, constraints or types; use the SQLite file for these activities.
  • Copy blocked: select the code manually, press ⌘C and paste with ⌘V.
  • File is not a database: open lab_training.sqlite, not a CSV or SQL text file renamed to .sqlite.
  • Decimal timing artifacts: date calculations may produce small floating-point differences. ROUND makes displayed minutes readable.

Column meanings

assays
  • assay_id: integer primary key (unique test identifier)
  • assay_name: test name
  • department: Chemistry or Hematology
  • specimen_type: compatible sample type
  • unit: unit for results and QC measurements
specimens
  • specimen_id: integer primary key
  • accession: synthetic unique text identifier
  • received_at: timestamp YYYY-MM-DD HH:MM:SS
  • source_area: invented Emergency, Ward or Outpatient
  • priority: STAT or Routine
  • specimen_type: Plasma, Whole blood or Serum
  • acceptance: Accepted or Rejected
  • rejection_reason: reason text, NULL if accepted
results
  • result_id: integer primary key
  • specimen_id: foreign key to specimens
  • assay_id: foreign key to assays
  • result_value: numeric measurement, NULL if pending; unit comes from assays
  • released_at: timestamp, NULL if pending
  • status: Final or Pending
qc_runs
  • qc_id: integer primary key
  • run_date: YYYY-MM-DD text
  • assay_id: foreign key to assays
  • control_lot: fictional lot identifier
  • control_level: Level 1 in this exercise
  • measured_value: numeric measurement in the assay unit
  • training_target: invented control target in the assay unit
  • training_sd: invented positive standard deviation in the assay unit
